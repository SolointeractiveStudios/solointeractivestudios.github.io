00 / Foundations

Establish identity integration and core data contracts before any platform-specific code is written.

Deliverables

  • Decide whether the comms platform reads the existing account table directly, or through a shared identity service
  • End-to-end authentication working: a request can be resolved to a known user
  • Canonical permission/role model defined (server roles, channel-level overrides)
  • API contract conventions documented (REST verbs, error format, pagination) for every later service to follow

Tech

04 / Voice Proof of Concept

Learn mediasoup's room, producer, and consumer model on one hardcoded test channel before adding lifecycle complexity.

Deliverables

  • One long-running mediasoup worker/router instance
  • WebRTC signaling (offer/answer/ICE) relayed through a SignalR hub
  • A bare test client that can join, publish audio, and hear other test users
  • Written reference notes on the producer/consumer/transport lifecycle, to guide Phase 5

Tech

mediasoupWebRTCSignalR
Highest unknown-unknowns — mediasoup is a low-level library, not a turnkey server. Budget extra time for the learning curve.

Depends on → Phase 3 (parallel-safe with separate people on each)

5

05 / Voice Manager & Dynamic Lifecycle

Replace the static test instance with the full on-demand spin-up, idle-timeout, and shutdown model.

Deliverables

  • Voice Manager service: checks for an existing instance per channel, starts one if absent
  • Connected-user tracking per voice instance
  • Configurable idle timer (default 5 min) that triggers automatic shutdown
  • Graceful handling of edge cases: user joins mid-spin-up, instance crash, simultaneous join race condition
  • Load test at simulated 5 / 10 / 50 / 100 user counts to confirm no architectural ceiling

Tech

mediasoupDockerSignalR
Riskiest phase in the roadmap — this is where the "self-hosted Discord" model either holds up under real concurrency or doesn't. Test failure modes deliberately, not just the happy path.

Depends on → Phase 4

6

06 / TURN/NAT & Containerization

Make voice connectivity reliable from outside a friendly office network, and make deployment repeatable.

Deliverables

  • coturn deployed with TURN credential rotation
  • Test calls from at least one connection behind a symmetric or corporate NAT
  • Docker Compose file covering Core API, messaging, Voice Manager, mediasoup nodes, Postgres, MinIO, and coturn
  • Documented firewall and port requirements for self-hosting

Tech

coturnDocker Compose
Watch for — NAT traversal failures are often silent. Test deliberately from multiple network types; office Wi-Fi isn't representative.

Depends on → Phase 5
